## Security Considerations

| Layer | Mitigation |
|-------|------------|
| **Network** | UFW firewall (22, 80, 443 only), Docker bridge networks isolate services; only `traefik.enable=true` containers (n8n-main, grafana) are reachable via the `proxy` network; other ports bound to 127.0.0.1 |
| **Transport** | TLS via Traefik + Let's Encrypt (auto-renewed), HTTP → HTTPS redirect |
| **Authentication** | n8n Basic Auth, Grafana Basic Auth, python-api assumes private network |
| **Execution** | Subprocess isolation, 60s timeout, no root in containers |
| **Scripts** | Read-only mount (`:ro`), venv isolation, no network restrictions |
| **Secrets** | `.env` generated by `env-maker.sh` (random secrets, mode 0600, gitignored), N8N_ENCRYPTION_KEY for credentials; `GITHUB_TOKEN` never written to `scripts/.git/config` |
| **Venv** | Corruption detection, auto-purge, system_site_packages=True (limited isolation) |

**Known Limitations:**
- python-api has no authentication (relies on network isolation)
- User scripts can make network calls (no egress filtering)
- Venvs share system site packages (base packages accessible)
- `docker.sock` is mounted read-only into Traefik, but socket access ≈ root on the host; hardening option: docker-socket-proxy
